📖 核心原理与使用方法

核心原理：Prefill（处理输入）= 算力密集 → 受 GPU TFLOPS 限制；Decode（逐 Token 生成）= 显存带宽密集 → 受 Memory Bandwidth 限制。每生成一个 Token，GPU 需把全部模型权重从显存读一遍。

使用方法：① 在下方选择/输入参数 → ② 橙黄底色 = 你来选择/输入（共 12 个输入点）；浅绿底色 = 从参数库自动联动（勿手动修改）；浅蓝底色 = 计算公式结果（自动更新）→ ③ 修改任意输入，所有结果实时联动更新。

注意事项：MoE 模型填「激活参数量」；长上下文场景 KV Cache 不可忽略；实际性能受软件栈/驱动/温度影响 ±20~30%。

        📐 核心公式速查

        • 模型权重体积：Weight(GB) = 激活参数(B) × 每参数字节数 例: 70×0.5 = 35 GB
        • 理论 Decode 速度：Tok/s = 显存带宽(GB/s) ÷ 权重(GB) 例: 1008÷35 = 28.8 tok/s
        • 实际 Decode 速度：Tok/s = 理论值 × 效率系数 例: 28.8×0.65 = 18.7 tok/s
        • KV Cache 体积：2×层数×KV头数×头维度×seq×bytes/1e9 例: 2×80×8×128×4096×2/1e9=1.34GB
        • Prefill 时间：T(ms)=2×参数(B)×提示长度÷FP16算力×1000 例: 2×70×512÷165×1000=434ms
        • 多卡 TP 速度：(带宽×卡数)÷权重×效率×通信系数 近似线性加速，有通信开销
        • 用户感知吞吐：Tok/s = 生成长度÷(Prefill+生成时间) 综合指标，最贴近实际体验
        精度与字节数：FP32=4B | FP16/BF16=2B | INT8=1B | INT4=0.5B | INT2=0.25B
